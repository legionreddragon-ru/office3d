# ДОРОЖНАЯ КАРТА ПРОДАЖИ И БЕЗОПАСНОСТИ
Зафиксирована 16.11.2026. Три подтрека, которые НЕЛЬЗЯ потерять.

## ПОДТРЕК A: ПРАВА ДОСТУПА (Этап 4)
Цель: разные люди = разные права, всё пишется в журнал.
- A1. Таблица users: id, login, role, created_at
- A2. Роли: admin (всё), operator (склад/чеки/ярмарки, БЕЗ Сервиса и Базы знаний), viewer (только чтение отчётов)
- A3. Вход: пароль офиса = admin; operator и viewer — свои пароли в secrets
- A4. audit_log: кто, что, когда (каждая запись, удаление, бэкап, вход)
- A5. Вкладка Сервис и кнопки лечения видны только admin
- Чек готовности: operator не может удалить операцию и не видит Сервис; в audit_log виден его вход

## ПОДТРЕК B: ПЛАТФОРМЫ Windows / Astra Linux / Mac (Этап 5)
Цель: офис ставится на любую ОС по инструкции за 30 минут.
- B1. backup.py на zipfile вместо PowerShell (бывший шаг 0c, перенесён сюда)
- B2. Автопоиск Tesseract: shutil.which + переменная TESSERACT_CMD
- B3. Установщик расписания: schtasks (Win) / cron (Linux) / launchd (Mac)
- B4. Уведомления: PowerShell (Win) / notify-send (Linux) / osascript (Mac)
- B5. install.bat + install.sh + INSTALL_ASTRA.md + INSTALL_MAC.md
- ПРАВИЛО-СТРАХОВКА (действует УЖЕ СЕГОДНЯ): вся сервисная логика только в .py,
  bat и sh — обёртки из двух строк. Нарушил правило = заплатил неделями потом.
- Чек готовности: офис поднят на чистой Astra в виртуалке по инструкции

## ПОДТРЕК C: ЛИЦЕНЗИИ И КЛЮЧИ (Этап 6)
Цель: платят — работает полностью, не платят — только читает.
- C1. Ключ OFFICE3D-XXXX-XXXX-XXXX; генератор license_gen.py хранится
  ВНЕ продаваемого архива, только у владельца
- C2. Привязка к hardware ID: один ключ = один компьютер
- C3. license_check.py при старте: ключа нет или не совпал = режим viewer
- C4. Онлайн-проверка раз в 24 часа (опция для подписочной модели)
- C5. LICENSE.txt в архиве + атрибуция иконок (CREDITS.md уже есть)
- Чек готовности: копия офиса на втором ПК без ключа открывается
  только для чтения, с ключом — полнофункционально
