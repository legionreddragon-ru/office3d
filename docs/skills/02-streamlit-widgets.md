# 02. Как лечить Streamlit-виджеты

## Симптомы (когда открывать этот файл)

- Загрузчик файлов показывает старое фото после записи операции
- Зелёное сообщение «Сохранено» не появляется после действия
- Кнопка срабатывает два раза или не срабатывает вообще
- Поменял код, а в браузере всё по-старому
- Автотест UI падает с «name 'os' is not defined»

## Золотые правила (выучить наизусть)

1. **НИКОГДА не присваивать st.session_state[ключ_виджета].**
   Виджет (file_uploader, text_input, selectbox) владеет своим ключом сам.
   Присвоение = тихая поломка состояния. Запрет с октября, урок v5-v7.

2. **Виджет очищается ТОЛЬКО сменой ключа через счётчик.**
   Правильно: key="upload_receipt_" + str(st.session_state["upload_counter"]),
   после записи counter += 1 и st.rerun(). Виджет рождается заново пустым.

3. **st.rerun() съедает st.success и st.warning.**
   Сообщение, поставленное ПЕРЕД rerun, исчезает вместе со страницей.
   Правильно: положить текст в обычный ключ session_state
   (st.session_state["flash"] = "..."), после rerun прочитать и показать,
   потом удалить ключ. Пример живой: flash_health в health_ui.py.

4. **F5 в браузере = новая сессия.** Ключи виджетов сбрасываются,
   счётчики в session_state обнуляются. Это норма, не баг.

5. **Поменял код файла = перезапусти офис.**
   Streamlit держит модули в памяти запущенного процесса.
   Закрыть чёрное окно → ярлык ОФИС-3D → пароль. Иначе видишь старый код
   и грешишь на новую заплатку (кейс с ярмарками 30.10).

6. **Все вкладки исполняются всегда.** Кнопки внутри неактивной вкладки
   существуют и выполняются при каждом прогоне страницы. Учитывать при
   автотестах и при дублирующих ключах (key должен быть уникален ВЕЗДЕ).

## Чек-лист лечения залипшего загрузчика

1. Открыть файл вкладки, найти file_uploader
2. Проверить: key содержит счётчик? Нет → добавить counter по правилу 2
3. Проверить: после записи операции counter увеличивается и вызывается rerun?
4. Перезапустить офис (правило 5)
5. Боевая проверка: загрузить фото → записать операцию → загрузчик пуст
6. autotest 10/10 → коммит

## Чек-лист лечения пропавших сообщений

1. Найти st.success/st.warning стоящие ПЕРЕД st.rerun()
2. Заменить на flash-ключ по правилу 3
3. Перезапустить офис
4. Боевая проверка: действие → сообщение видно
5. autotest → коммит

## Чек-лист «поменял код, а ничего не изменилось»

1. Сохранён ли файл? (Ctrl+S в Блокноте, звезда в заголовке ушла?)
2. Перезапущен ли офис? (правило 5)
3. F5 в браузере после перезапуска офиса
4. Всё ещё старо → py_compile файла, потом autotest, отчёт ИИ

## Чек-лист автотеста UI (для ИИ и для будущего себя)

1. AppTest.from_function НЕЛЬЗЯ: вырезает импорты модуля («os is not defined»)
2. Только AppTest.from_file через файл-обёртку:
   обёртка делает import модуля и вызывает m.render()
3. Кнопки искать по label: for b in at.button: if "сирот" in b.label
4. Клик: btn.click().run()
5. Реальные данные не трогать: патчить db.DB_PATH и ACC_DIR на temp-папку
